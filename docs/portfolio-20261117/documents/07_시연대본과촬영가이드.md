# VisionQC 시연 대본과 촬영 가이드

기준일: 2026-11-17 · 문서 버전: 2.0

기준: https://github.com/mycom0216/VisionQC/tree/b7ed874 + 이번 로컬 개선 코드. 기존 개발 이력은 저장소 자료이며, 이번 검증은 별도 표기합니다.

## 1. 영상 목적
실제 앱에서 이미지 검사→NG 이력·CAM→CSV→검토→통계→권한·백업 흐름을 보여준다. 촬영은 운영 DB와 분리된 시연 DB를 사용했다. 시연 영상은 설명 자막이 있는 화면 녹화 편집본이며 음성 내레이션은 포함하지 않는다. 전체 작업 대기 구간은 줄였으며 추론 결과를 합성하지 않았다.

편집된 MP4의 길이·구간과 위 재촬영 대본의 시각은 다를 수 있다. 동봉 자막 파일은 실제 편집 영상에 맞춘다.

## 3. 재촬영 체크리스트
실행 전 모델과 이미지 경로, 분리 DB, 한글 UI 배율, 알림 차단 여부, 남은 디스크와 녹화 범위를 확인한다. 앱 창만 촬영하고 로그인 비밀번호 입력은 제외한다. 시작→50장 처리→NG 선택→CAM 켜기/끄기→CSV 저장→검토 메모→통계→백업 순서로 진행한다. 오류 장면은 별도 손상 fixture로 보여주고 일반 이미지 수와 분리한다.

## 4. 예상 질문
| 질문 | 답변의 핵심 |
|---|---|
| 정확도는 얼마인가? | 고정 시험 50장 정확도 98%, 불량 재현율 92.9%, FN1. 현장 정확도 아님 |
| 불량 위치를 검출하나? | CAM 참고 위치다. 검출 박스·유형은 미구현 |
| 100% 지표가 보이는 이유는? | 검토한 소수 행으로 계산한 재판정 지표다. 독립 모델 평가와 다름 |
| 왜 ERROR가 필요한가? | 판정 실패가 양품으로 통과하는 것을 막기 위해 구분 |
| 모델 교체 시 무엇을 맞추나? | 입력 크기·RGB/CHW·정규화·클래스 순서·출력 계약 |
| 백업만 있으면 이미지도 복원되나? | DB에 경로만 저장하므로 이미지·모델 파일 별도 보존 |
| 다음 고도화는? | 검출 모델 계약·라벨·학습·평가·좌표 변환을 먼저 연결하고 실카메라 시험 |
