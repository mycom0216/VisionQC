## 1. 적용 규칙
구현은 현재 코드 기준이다. “부분”은 해당 ID의 모든 확장 기능이 완성됐다는 뜻이 아니다. P0는 시연 필수, P1은 후속 고도화다.

## 2. 비기능 요구사항
| ID | 요구 | 검증·수용 기준 | 현황 |
|---|---|---|---|
| NFR-01 | 응답성·메모리 | 비동기 큐, 용량 제한; 대상 PC·데이터·warmup 조건과 mean/p95 명시 | 구조 구현, 현장 SLA 없음 |
| NFR-02 | 신뢰성 | 이미지 단위 오류가 전체 회차를 중단하지 않음, 저장 실패 별도 보고 | 단위·통합 검증 |
| NFR-03 | 보안 | 비밀번호 평문 저장 금지, 3역할과 잠금, 입력 CSV 수식 보호 | 코드·회귀 검증 |
| NFR-04 | 추적성 | 회차의 모델 해시·임계값·입력, 원 판정과 정정 구분 | 구현 |
| NFR-05 | 복구성 | SQLite 무결성 검사, 복원 전 백업, 이력 삭제 전 백업 | 자동 시험+수동 백업 확인 |
| NFR-06 | 유지보수성 | Core/Imaging/Inference/Data/App 의존성 분리, 테스트 가능한 인터페이스 | 구현 |
| NFR-07 | 데이터 시간 | UTC 저장, 로컬 표시, 같은 날 범위 양끝 포함·역전 거부 | 이번 범위 시험 통과 |

## 3. 후속 요구사항
FR-16 검출 모델: 학습·검증된 객체 검출 ONNX의 입출력 계약, 좌표 역변환, NMS, 실제 박스·유형 표시를 한 단위로 검증한다. 현재 미구현이다.

FR-17 장비 검증: 실카메라 연결·해제·재연결·광량 변화와 장시간 영상/감시 시험을 수행한다. 실장비와 시험 시간이 확보돼야 완료 판정한다.

## 4. 변경 관리
이번 FR-14는 CSV 부분 구현이며 PDF·전체 이력·최신 정정·모델 메타데이터를 포함한 종합 리포트까지 완료한 것은 아니다. UI의 검토 기반 100% 표시는 소수 검토 행의 계산으로, 시험셋 모델 정확도로 사용하지 않는다. 변경된 요구 ID는 개발일정표 및 검증보고서와 함께 관리한다.
