# VisionQC 시스템 설계서

기준일: 2026-11-17 · 문서 버전: 2.0

기준: https://github.com/mycom0216/VisionQC/tree/b7ed874 + 이번 로컬 개선 코드. 기존 개발 이력은 저장소 자료이며, 이번 검증은 별도 표기합니다.

## 1. 기술 구성과 의존성
| 계층 | 주요 기술 | 책임 |
|---|---|---|
| App | C# · .NET 10 · WPF · CommunityToolkit.Mvvm | 화면 상태·사용자 입력·권한 기반 탭·서비스 구성 |
| Core | C# 인터페이스·Channel·도메인 로직 | 판정·파이프라인·통계·정정·인증 정책 |
| Imaging | OpenCvSharp | 폴더·감시·영상 공급, 리사이즈·색상·정규화·ROI |
| Inference | ONNX Runtime CPU | 분류 실행·softmax·선택 CAM·모델 해시 |
| Data | Microsoft.Data.Sqlite | 결과·계정·감사·백업 |
| Training | Python · PyTorch · ONNX · NumPy/OpenCV | 학습·내보내기·분할·평가·CAM 추가 |

App이 구현체를 조합하고, Core는 외부 저장·추론 구현에 의존하지 않는다. 모든 기술을 개발 언어로 부르지 않는다. SQLite는 DBMS, ONNX는 모델 교환 형식, WPF는 UI 프레임워크다.

## 2. 검사 흐름
이미지 공급 → 용량 제한 Channel(기본 8) → 전처리 → ONNX → 임계값 판정 → SQLite → UI 진행 통지. 기본 워커 1. 회차 시작에는 모델 파일명·해시·소스·임계값을 남기고 끝나면 Completed/Cancelled/Failed를 기록한다. 진행 중 한 장의 디코드·추론 예외는 ERROR로 전환한다. 저장 실패는 집계하여 검사 결과와 구분한다.

## 3. 모델 입출력 계약
입력은 float32 [1,3,224,224], RGB·CHW, x/255 후 mean=(.485,.456,.406), std=(.229,.224,.225). 첫 출력 logits 2개에서 softmax index 1을 불량 점수로 해석한다. 이진 클래스는 0 good, 1 defect다. 선택 출력 cam은 [1,1,7,7]. 모델 버전은 SHA-256 앞 12자리이며 정식 등록부는 아직 없다. 이번 CAM 모델의 실제 버전은 222e8732c487다.

## 4. 정정과 통계
원 판정은 inspection_result에 보존한다. 정정은 result_review에 추가하고 최대 id가 최신이다. 통계 화면은 원 판정을 집계한다. 따라서 정정 화면의 유효 판정과 원 판정 통계가 다를 수 있다. UI 검토 기반 지표의 분모는 검토한 행이므로 모델의 독립 시험 성능과 구분한다.

## 5. 권한 매트릭스
| 기능 | Operator | Engineer | Admin |
|---|---|---|---|
| 검사·이력·통계·표시 결과 CSV | 허용 | 허용 | 허용 |
| 재판정·정정·모델/임계값/ROI 설정 | 제한 | 허용 | 허용 |
| 계정·감사·데이터 관리 | 제한 | 제한 | 허용 |

권한 없는 탭 숨김과 주요 서비스의 권한 확인을 함께 사용한다. 사용자 관리에서는 저장소의 현재 관리자 상태를 다시 확인한다. 무조작 만료는 검사·감시 중 제외한다. 감사 로그는 API 수준 추가 전용이며 DB 파일 직접 수정까지 막는 변조 방지 로그가 아니다.

## 6. 데이터·복구·배포
SQLite는 WAL 모드, 외래 키 활성화, busy_timeout=5초다. 새 DB는 CREATE TABLE IF NOT EXISTS, heatmap은 구 DB에 열 추가로 대응하며 정식 버전 마이그레이션 도구는 없다. 이미지와 모델 파일은 외부 파일이고 DB에는 경로/버전만 저장하므로 별도 보존이 필요하다. 복원 전 DB 안전 사본과 재로그인을 사용한다. 자동 백업은 앱이 켜지고 로그인된 동안만 동작한다.

배포 대상은 Windows + .NET 10 Desktop Runtime이다. 기존 tools/publish.ps1을 사용하며 설치 프로그램·코드 서명은 후속이다. 실카메라·PLC·생산라인 연동은 별도 장비 계약과 시험이 필요하다.

## 7. 이번 설계 변경
HistoryCsv는 Core에서 TextWriter에 쓰므로 UI 없이 검증할 수 있다. UI는 조회 결과 배열을 스냅샷으로 고정하고 SaveFileDialog를 거쳐 UTF-8 BOM의 임시 파일에 쓴 뒤 목적 파일로 교체한다. 숫자·시각은 문화권 독립 형식이다. 외부 텍스트의 수식 접두부를 보호하며 원 판정과 최대 500건 범위를 명시한다. HistoryPeriod는 이력·통계·재판정에 공통 적용해 날짜 역전을 일관되게 거부한다.
