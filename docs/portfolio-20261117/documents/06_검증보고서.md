## 3. 집계 해석
전체 207건 중 모델 조건 테스트 2건은 환경변수가 없으면 조기 반환한다. 따라서 전체 테스트 통과만으로 실제 모델을 검증했다고 해석하지 않았다. 실제 모델 경로와 Python 점수 케이스를 설정해 해당 2건을 별도로 활성 실행했다. 이 재실행을 합산하지 않는다.

기존 50장 시험셋을 시연 준비와 UI에서 각각 한 번 검사했다. 따라서 UI DB는 정상 처리 100건 + 손상 fixture 1건이며, 이 중 NG는 26건이다. 서로 다른 이미지 100장 평가가 아니다. 검토 화면의 2건 기반 100%는 확인 메모에서 파생된 지표이며 시험셋 성능으로 쓰지 않는다.

## 4. 성능 측정 경계
시연 준비 회차의 전처리+추론+판정 평균 39.2ms, p95 37ms, 최대 426ms. 초기 호출 포함, 동일 PC·50장·CAM 모델. 저장/화면 갱신은 제외하며 평균·p95는 보간하지 않는 최근접 순위 규칙이다. 이전 README의 20.5ms와 조건이 다르므로 이번 수치와 혼합하지 않는다.

## 5. 이번 검증에서 제외한 항목
FlaUI 10건 전체 UI 회귀는 이번에 재실행하지 않았다. 대신 본문에 명시한 실제 화면 흐름을 수동 자동 조작으로 확인했다. 실카메라, 장시간 감시, 장비 해제·재연결, 검출 박스·유형, 실제 운영 DB 복원·삭제, 인스톨러 서명은 검증 완료로 표시하지 않는다. 기존 복원·삭제 로직은 회귀 시험 결과와 실제 현장 시험을 구분해야 한다.

## 6. 재현 명령
```powershell
dotnet build VisionQC.slnx -c Release
dotnet test VisionQC.Tests -c Release
python -m unittest discover -s training -p 'test_*.py' -v
# 실제 모델 시험은 VISIONQC_PARITY_MODEL, VISIONQC_PARITY_MODEL_CAM,
# VISIONQC_PARITY_CASES 설정 후 OnnxParityTests/OnnxCamOutputTests 필터 실행
```
모델·이미지는 저장소에 없다. 학습 산출물과 전처리 규약을 먼저 확보한다. 제공한 로컬 demo-assets는 재배포용 자료 묶음에서 제외했다. 시연용 계정·DB도 배포 자료에 포함하지 않는다.
