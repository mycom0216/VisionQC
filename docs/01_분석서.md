### 1.2 공고에서 뽑은 공통 요구

1. **C# + WPF(또는 WinForms) 검사 응용프로그램** — 거의 모든 C# 공고에 등장
2. **영상처리**: OpenCV 계열 (C#에서는 OpenCvSharp / Emgu CV)
3. **딥러닝 외관검사**: 분류·검출·세그멘테이션(YOLO 등), 이상검출. 신입은 "개발 경험"이 아니라 "프로젝트로 보여줄 수 있는가"가 관건
4. **카메라·장비 연동**: 카메라 SDK, 트리거, 조명, 컨베이어/PLC (상위 경력 공고)
5. **현장 운영성**: 장비 설치, 안정화, 고객 지원, 로그·이력

### 1.3 조사의 한계 (확인 필요)

- 검색 도구로 한 번 모은 결과이며 사람인·잡코리아·점핏 목록을 직접 순회한 전수 조사가 아니다.
- 세이지리서치 공고는 원문 페이지가 접근 차단(403)되어 **검색 요약 기준**이다. 요강 원문은 직접 확인이 필요하다.
- 마감 여부 미확인. 옵트에이아이 공고는 마감일이 2025-12-02로 이미 지났다.
- 점핏 공고는 대부분 경력 요구라 신입 지원 대상에서 빠진다.

## 2. 프로젝트 정의

### 2.1 선정 주제

**VisionQC — 제조 부품(PCB 등) 외관 이미지를 AI로 검사해 양품/불량을 판정하고 이력을 관리하는 WPF 데스크톱 프로그램**

선정 이유
- 세이지리서치(1순위)·이노메트릭스·옵트에이아이가 공통으로 요구하는 **C# + WPF + OpenCV + 딥러닝**을 한 프로젝트에서 모두 보여줄 수 있다.
- 실제 카메라·장비 없이도 **공개 데이터셋과 이미지 폴더/USB 카메라**로 시연 가능하다(§6 리스크 참고).
- 기존 포트폴리오(ChatApp: C# 서버/클라이언트, JobFit: Java/Spring)와 겹치지 않는 영역(영상·AI 추론)이다.

### 2.2 WPF vs WinForms

**WPF로 결정(권고).** 공고에 "WPF 기반 검사 UI"가 명시되고, 이미지 오버레이·실시간 갱신에 데이터 바인딩(MVVM)이 유리하다. 기존 ChatApp이 WinForms이므로 두 가지 UI 기술을 모두 쓴 이력이 생기는 장점도 있다.

### 2.3 목표와 비목표

| 목표 | 비목표(이번 범위 밖) |
|---|---|
| 이미지 입력 → 전처리 → AI 추론 → 판정 → 결과 표시·저장 | 실제 생산라인 PLC·컨베이어 제어 |
| 불량 위치 표시(바운딩 박스/히트맵), 판정 이력 조회 | 3D 센서·라인 프로파일러 |
| 모델 교체 가능한 추론 구조(ONNX) | HALCON/MIL 등 상용 라이브러리 |
| 검사 성능 지표 측정(재현율·오검출률·처리시간) | 클라우드·다중 설비 통합 관제 |

## 5. 비기능 요구사항

| 구분 | 요구 | 측정 방법 |
|---|---|---|
| 성능 | 1장 검사(전처리+추론+표시) **CPU 기준 500ms 이내**를 목표로 하고 실제 측정값을 기록 | 처리시간 로그, 100장 평균·p95 |
| 정확도 | 데이터셋 기준 **불량 재현율(Recall) 우선**. 목표치는 데이터셋 확정 후 정하되, 미검출(불량을 양품 판정)을 오검출보다 더 큰 오류로 취급 | 혼동행렬, Recall/Precision/F1 |
| 응답성 | 추론 중에도 UI가 멈추지 않음(비동기 처리) | 수동·UI 테스트 |
| 안정성 | 손상 이미지·모델 파일 누락 시 오류 표시 후 계속 동작 | 예외 시나리오 테스트 |
| 추적성 | 모든 판정에 모델 버전·임계값·시각 기록 | DB 스키마 확인 |
| 확장성 | 모델·이미지 소스 교체 시 UI 코드 수정 없음 | 인터페이스 설계 검토 |
| 이식성 | Windows 10/11, .NET 8 이상 | 설치·실행 검증 |

> 위 수치는 **목표**이며 구현·측정 전에는 달성했다고 쓰지 않는다.

## 6. 데이터 분석

### 6.1 학습·검증 데이터 후보

실장비 이미지가 없으므로 공개 데이터셋을 쓴다. **사용 전 각 데이터셋의 라이선스·이용 조건을 직접 확인해야 한다.**

| 후보 | 성격 | 적합도 |
|---|---|---|
| MVTec AD | 산업 외관 이상검출 벤치마크(정상 위주 학습, 비정상 검증) | 이상검출 접근에 적합. 상업 이용 제한 여부 확인 필요 |
| DeepPCB | PCB 결함 검출(위치 라벨) | 검출(YOLO) 접근에 적합 |
| 직접 촬영 | 스마트폰·USB 카메라로 부품 촬영 | 시연용. 불량 샘플 확보가 어려움 |

### 6.2 접근 방식 비교

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 분류(양품/불량) | 가장 단순, 학습 쉬움 | 불량 위치 불명 | MVP 기본 |
| 검출(YOLO 계열) | 위치·유형 표시, 공고 키워드와 일치 | 박스 라벨 필요 | **목표 방식** |
| 이상검출(비지도) | 불량 샘플이 적어도 됨 | 임계값 조정 어려움 | 2차 확장 후보 |

권고: **검출 모델(ONNX로 변환)을 목표로 하되 분류 모델을 먼저 붙여 파이프라인을 완성**한 뒤 교체한다. 모델 학습은 Python에서 하고, C# 앱은 ONNX Runtime으로 추론만 한다(공고의 C# + Python 병용 구조와 일치).

### 6.3 핵심 데이터 엔티티 (상세는 설계 단계 데이터정의서에서)

`User`, `InspectionJob`(검사 회차), `InspectionResult`(이미지 1장 결과), `Defect`(검출된 불량 1건: 유형·박스·신뢰도), `ModelVersion`, `Setting`, `AuditLog`

## 10. MVP 범위와 완료 기준(분석 결론)

**MVP = FR-01, 03, 04, 05, 06, 07, 08, 11** (폴더 이미지 → 추론 → OK/NG·불량 표시 → 이력 저장·조회 → 설정)

완료 기준
1. 검증용 이미지 100장 이상 일괄 검사가 UI 멈춤 없이 완료된다.
2. 혼동행렬과 Recall/Precision, 평균·p95 처리시간이 문서에 **실측값**으로 남는다.
3. 손상 이미지·모델 누락 등 예외 시나리오 테스트가 통과한다.
4. 판정 이력에 모델 버전·임계값이 기록된다.
