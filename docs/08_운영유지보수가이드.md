# VisionQC 운영·유지보수 가이드

작성일 2026-11-13 · 대상: 설치·운영하는 엔지니어/관리자 · 근거: 현재 코드(커밋 기준)와 실제 실행 확인.
**이 문서는 개인 프로젝트의 단일 PC 기준 절차**이며, 실제 생산 현장 요구(이중화·원격 관제·자동 알림 등)는 다루지 않는다.

## 1. 설치

1. 배포 폴더 만들기(개발 PC): `powershell -ExecutionPolicy Bypass -File tools\publish.ps1`
   - 기본은 **프레임워크 종속**(약 114MB). 대상 PC에 **.NET 10 Desktop Runtime (x64)** 이 필요하다.
   - `-SelfContained` 를 주면 런타임까지 포함해 대상 PC에 .NET 설치가 필요 없다(대신 폴더가 더 큼 — 이 방식은 이 문서 작성 시점에 실행 확인을 하지 않았다).
2. `publish\` 폴더를 대상 PC의 원하는 위치(예: `C:\VisionQC`)에 통째로 복사한다.
3. **모델(.onnx)은 포함되지 않는다.** 설정 탭에서 지정한다(§7).
4. 코드 서명을 하지 않으므로 처음 실행할 때 Windows SmartScreen 경고가 뜰 수 있다. 설치 프로그램(인스톨러)은 만들지 않았다.

확인한 것: 배포 폴더의 `VisionQC.App.exe`를 실행해 최초 관리자 생성 → 50장 검사 → 이력 저장까지 정상 동작(결과가 개발 빌드와 동일: OK 37 / NG 13).

## 2. 첫 실행과 계정

- 처음 실행하면 **관리자 계정 만들기** 화면이 뜬다. 아이디는 영문·숫자·`_ . -` 3~32자, 비밀번호는 8자 이상이며 아이디를 포함할 수 없다.
- 이후 **관리 탭**에서 작업자(Operator)·엔지니어(Engineer)·관리자(Admin) 계정을 만든다.

| 역할 | 할 수 있는 일 |
|---|---|
| 작업자 | 검사 실행(수동·폴더 감시), 이력·통계 조회 |
| 엔지니어 | + 재판정·정정, 모델·임계값·ROI·자동 로그아웃 시간 변경 |
| 관리자 | + 사용자 관리, 감사 로그 조회, DB 백업 |

- **비밀번호를 잊으면 자체 복구가 없다.** 다른 관리자가 있으면 관리 탭에서 재설정(잠금도 풀림), 마지막 관리자를 잃었다면 §9를 따른다.
- 5회 연속 로그인 실패 시 10분 잠금. 관리자가 비밀번호를 재설정하면 즉시 풀린다.
- 자동 로그아웃: 마우스·키보드 입력이 없으면 설정한 시간(기본 15분, 1~480분) 뒤 로그아웃. **검사·감시가 돌고 있는 동안은 로그아웃되지 않는다**(무인 연속 검사가 끊기지 않게 한 선택). 그 대신 **감시 중에는 로그인된 세션이 열려 있으므로** 자리를 비울 때는 화면 잠금(Windows+L)을 쓴다.

## 3. 파일 위치

| 파일 | 기본 위치 | 비고 |
|---|---|---|
| 이력·계정·감사 DB | `%LOCALAPPDATA%\VisionQC\visionqc.db` (`-wal`, `-shm` 보조 파일이 같이 생김) | 실행 인자 `--db` |
| 설정 | `%LOCALAPPDATA%\VisionQC\settings.json` | `--settings` |
| 백업 | `%LOCALAPPDATA%\VisionQC\backup\` | `--backup-dir` |

`%LOCALAPPDATA%`는 Windows 사용자별 폴더다 — **Windows 계정이 다르면 DB도 따로** 생긴다. 여러 사람이 같은 DB를 쓰려면 `--db`로 공유 경로를 지정한다(동시 사용·네트워크 드라이브 안정성은 확인하지 않았다).

실행 인자(이번 실행에만 적용, 저장되지 않음): `--folder` `--model` `--threshold` `--db` `--settings` `--backup-dir` `--autorun` `--tab history|review|stats|settings|admin`. **비밀번호는 인자로 받지 않는다.**

## 4. 일상 운영

- **수동 검사**: 폴더 선택 → 시작. 끝나면 "완료" 메시지와 OK/NG/ERROR 집계.
- **폴더 감시(연속 검사)**: "폴더 감시" 체크 후 시작. 시작 이후 폴더에 새로 생기는 이미지(jpg·png·bmp·tif)를 자동 검사하고 **중지 버튼으로 끝낸다**(이력에는 "Cancelled"로 남는 것이 정상).
  - 새 파일은 약 1초 안에 잡힌다(0.5초 간격 확인, 크기·수정시각이 두 번 같고 다른 프로세스가 쓰는 중이 아닐 때).
  - 30초가 지나도 쓰기가 안 끝나는 파일은 그대로 검사해 ERROR로 기록한다(조용히 빠지지 않음).
  - 파일 수만 장 이상 쌓이는 폴더는 폴링 비용이 커지므로 **처리 끝난 파일을 다른 폴더로 옮기는 운용**을 권한다(이동 기능은 없음 — 외부 스크립트로).
  - 감시 폴더가 사라지거나 읽을 수 없는 상태가 연속 10번 이어지면 작업이 실패로 끝난다.
- **ERROR는 양품이 아니다.** 손상 이미지·읽기 실패·추론 실패. 이력에서 사유를 확인한다.
- **재판정 탭**: 오판을 정정하면 정정 이력이 쌓이고, 임계값을 바꿔 보는 미리보기는 저장된 판정을 바꾸지 않는다. 임계값을 실제로 바꾸는 곳은 설정 탭(엔지니어 이상)이다.

## 5. 백업과 복원

**백업**(관리자): 관리 탭 → "DB 백업".
- `VACUUM INTO`로 한 시점의 일관된 사본을 `visionqc_YYYYMMDD_HHMMSS.db`로 만들고, 사본을 열어 무결성 검사(`PRAGMA integrity_check`)를 통과해야 성공으로 표시한다. 앱이 검사 중이어도 된다.
- 폴더에 최신 **10개**만 남기고 오래된 `visionqc_*.db` 백업을 지운다(다른 파일은 건드리지 않는다). 지운 개수는 감사 로그와 화면에 표시된다.
- **자동 예약 백업은 없다.** 운영 주기(예: 교대 종료 때, 하루 1회)를 정해 **사람이 눌러야 한다.** 필요하면 Windows 작업 스케줄러로 별도 스크립트를 만들어야 한다(미구현).
- **백업에는 계정(비밀번호 해시)과 감사 로그가 들어 있다.** 백업 폴더의 접근 권한을 DB와 같게 관리하고, 같은 디스크에만 두지 말고 다른 저장 장치에도 복사한다.

**복원**(수동 — 복원 기능은 앱에 없다):
1. 앱을 모두 종료한다.
2. 현재 `visionqc.db`, `visionqc.db-wal`, `visionqc.db-shm`을 다른 곳에 옮겨 둔다(복원이 잘못됐을 때 되돌리기 위해).
3. 복원할 `visionqc_*.db`를 `visionqc.db`라는 이름으로 복사한다. **`-wal`/`-shm` 파일은 반드시 지운다**(남아 있으면 이전 내용이 섞인다).
4. 앱을 실행해 로그인되는지, 이력이 보이는지 확인한다. 복원 시점 이후의 계정 변경·검사 이력은 사라진다.

## 6. 용량 산정 (실측 기준)

- 검사 결과 1건당 DB는 약 **183바이트**(인덱스 포함, 실제 스키마로 2만 건을 넣어 측정). 불량 위치를 쓰는 검출 모델에서는 `defect` 행이 추가되어 더 커진다(분류 모델은 `defect`를 쓰지 않음).
- 예: 초당 1장을 24시간 검사하면 하루 86,400건 ≈ **약 15MB/일**, 백업 10개 보관 시 그 10배 이하.
- **이력은 자동 삭제되지 않는다.** 보관 기간 정책과 정리 도구는 미구현이므로, 필요하면 백업을 보관한 뒤 DB를 새로 시작하는 식으로 수동 운용한다. 이미지 파일 자체는 DB에 들어 있지 않고 원래 폴더에 남는다(이력에는 경로만).

## 7. 모델 교체 절차

모델은 학습 스크립트(`training/`)가 내보낸 ONNX다. **규약**(클래스 0=양품·1=불량, logits 출력, 전처리 = INTER_AREA 리사이즈 + RGB + ImageNet 정규화, 입력 224px 또는 설정과 일치)을 지키지 않으면 판정이 조용히 틀린다.

교체 전(개발 PC):
1. 새 모델을 학습하고 `report.json`의 시험셋 지표를 **현재 모델과 같은 시험셋**으로 비교한다. 시험셋이 작으면(수십 장) 차이가 우연일 수 있다.
2. `training/parity_cases.py`로 파이썬 점수를 뽑아 `dotnet test --filter OnnxParityTests`(환경변수 `VISIONQC_PARITY_MODEL`, `VISIONQC_PARITY_CASES`)로 **C#과 점수가 일치(오차 < 1e-4)** 하는지 확인한다.
3. 모델 카드(`model_card.json`)의 권장 임계값을 참고하되, 최종 임계값은 실제 현장 이미지로 정한다.

교체(운영 PC, 엔지니어 이상):
4. 새 모델 파일을 별도 이름으로 복사해 둔다. **이전 모델 파일은 지우지 않고 보관**한다(롤백용).
5. 설정 탭에서 모델 경로와 임계값을 바꿔 저장한다. 감사 로그에 `모델 old.onnx→new.onnx · 임계값 …`이 남는다.
6. 알려진 양품·불량 샘플 폴더로 검사해 기대한 판정이 나오는지 확인한다.

롤백: 설정 탭에서 이전 모델 경로와 임계값으로 되돌려 저장한다.

주의: 검사 회차(`inspection_job`)마다 **모델 파일 이름과 버전(SHA-256 앞 12자리)** 이 기록되지만, 이력·통계·재판정 화면에는 모델별 필터가 없다. 교체 전후를 따로 보려면 DB에서 직접 조회한다:
```sql
SELECT j.model_name, j.model_version, COUNT(*) AS n,
       SUM(r.verdict='NG') AS ng, SUM(r.verdict='OK') AS ok
FROM inspection_result r JOIN inspection_job j ON j.id = r.job_id
GROUP BY j.model_version;
```
ROI를 쓰는 모델은 **학습 때와 같은 영역으로 학습한 모델**이어야 한다.

## 8. 장애 대응

| 증상 | 가능한 원인 | 조치 |
|---|---|---|
| "모델이 설정되어 있지 않습니다" | 설정 탭에서 모델을 지정하지 않음 | 엔지니어가 설정 탭에서 `.onnx` 지정 후 저장 |
| "모델을 열 수 없습니다" | 파일 이동·삭제, 손상, 규약이 다른 ONNX | 경로 확인, 이전 모델로 롤백(§7). 파일을 `training/evaluate.py`로 열어 보면 모델 문제인지 앱 문제인지 구분 가능 |
| "이미지 폴더를 찾을 수 없습니다" | 폴더 이동·네트워크 드라이브 끊김 | 경로·연결 확인 후 다시 선택 |
| 결과가 ERROR로 쌓임 | 손상·미지원 이미지, 읽기 권한 | 이력의 사유 확인. 감시 중이면 쓰는 중이던 파일일 수 있음(30초 후 ERROR 처리됨) |
| 모든 판정이 NG(또는 OK)로 쏠림 | 조명·촬영 조건 변화, 전처리/입력 크기 불일치, ROI 설정, 임계값 | 설정 탭의 ROI·임계값 확인, 재판정 탭으로 점수 분포 확인, 학습 때와 같은 조건인지 점검 |
| "이력 저장 실패 n건" | 디스크 가득, DB 파일 잠김·권한 | 디스크 여유·권한 확인. 저장 실패한 결과는 화면에는 보이지만 이력에는 없다 |
| 앱이 시작하자마자 "이력 DB를 열 수 없습니다" | DB 파일 손상·권한 | 백업에서 복원(§5). 원본은 옮겨 두고 분석 |
| 설정이 기본값으로 돌아감 / 시작 시 "설정 알림" | `settings.json`이 깨졌거나 값이 범위 밖 | 알림 문구 확인. 설정 탭에서 다시 저장하면 정상 파일로 덮어씀 |
| 로그인이 계속 거부됨 | 비밀번호 오류, 5회 실패 잠금(10분), 비활성 계정 | 관리자가 비밀번호 재설정(잠금 해제 포함) 또는 활성화 |
| "(※ 감사 로그 기록 실패)" 표시 | 감사 기록 쓰기 실패 | 업무(검사·정정)는 정상 처리됨. DB 상태·디스크를 점검하고 백업 |
| 화면이 느려지거나 메모리가 커짐 | 이력이 매우 많음(조회는 최대 500건씩), 감시 폴더 파일 과다 | 처리 끝난 파일 이동, 이력 정리(§6) |

앱은 별도 로그 파일을 남기지 **않는다**(업무 사건은 감사 로그, 오류는 화면 메시지). 원인 분석이 어려우면 오류 메시지를 그대로 기록하고 재현 절차를 남긴다.

## 9. 관리자 계정을 모두 잃었을 때 (최후 수단)

앱에는 복구 경로가 없다 — **DB 파일에 접근할 수 있는 사람은 사실상 최고 권한자**라는 뜻이기도 하다. 그래서 DB·백업 폴더의 파일 권한 관리가 중요하다.
1. 앱을 종료하고 `visionqc.db`를 백업해 둔다.
2. 계정 표를 비운다: `DELETE FROM user_account;` (SQLite 도구 사용). 감사 로그·검사 이력은 남지만 **모든 계정이 사라진다.**
3. 앱을 실행하면 "관리자 계정 만들기" 화면이 다시 뜬다. 새 관리자를 만들고 필요한 계정을 다시 만든다.
4. 이 작업이 있었다는 사실은 자동으로 기록되지 않으므로(앱 밖의 작업) 별도로 기록해 둔다.

## 10. 점검 체크리스트

- [ ] 관리자 계정이 2개 이상이다(한 명을 잃어도 복구 가능).
- [ ] 정기 백업 주기가 정해져 있고 다른 저장 장치에도 복사한다.
- [ ] DB·백업·설정 폴더에 일반 사용자 쓰기 권한이 없다.
- [ ] 퇴사·전보한 사람의 계정은 비활성화했다(삭제 기능은 없음).
- [ ] 모델 파일의 이전 버전을 보관하고 있다.
- [ ] 자리를 비울 때 화면을 잠그는 규칙이 있다(특히 감시 중).

## 11. 알려진 한계

- 카메라(UVC·산업용) 입력, 자동 예약 백업, 이력 자동 정리, 복원 도구, 원격 알림, 인스톨러·코드 서명은 없다.
- 불량 위치 박스 표시와 검출 모델은 아직 없다(통계의 불량 유형도 비어 있음).
- 성능 수치는 이 문서 작성 PC 한 대에서 잰 것이다([07_성능측정결과.md](07_성능측정결과.md)).
