# 불량 위치 히트맵(CAM) — 방식과 위치 정확도 실측

작성일 2026-11-13 · 코드: `training/add_cam_output.py`, `training/eval_cam.py`, `VisionQC.Core/Heatmap.cs`, `VisionQC.App/HeatmapRenderer.cs`

> **요약**: 분류 모델에서 "불량 판정에 기여한 위치"를 7×7 격자로 뽑아 이미지 위에 반투명하게 겹쳐 보여 준다. 가장 뜨거운 칸은 실제 불량과 자주 겹치지만(전체 97.8%, 우연 30.2%) 열이 넓게 퍼져서 **정확한 윤곽이 아니라 "대략 이 부근"** 이다. 박스를 그리는 검출 모델이 아니다.

## 1. 방식 (Class Activation Mapping)

ResNet 계열 분류기는 `마지막 특징맵 F[c,h,w] → 전역 평균 풀링 → FC` 로 끝난다.

```
logit_k = Σ_c W[k,c] · mean_hw F[c] + b_k
CAM[h,w] = Σ_c (W[1,c] − W[0,c]) · F[c,h,w]          (불량 쪽 증거 − 양품 쪽 증거를 위치별로 분해)
mean_hw CAM = (logit_1 − logit_0) − (b_1 − b_0)       ← 항등식
```

- **재학습·새 가중치·새 데이터 없이** 기존 ONNX 그래프에 `Mul` + `ReduceSum` 노드만 덧붙여 `cam` 출력(`[1,1,7,7]`)을 만든다(`add_cam_output.py`). 원래 `logits` 출력은 그대로다.
- 앱은 `cam` 출력이 있는 모델이면 히트맵을 함께 받고, 없으면(기존 `model.onnx`) 기존과 똑같이 동작한다.
- 이력에는 **NG 결과만** 히트맵을 저장한다(결과 1건당 약 224바이트). ROI를 썼다면 격자가 덮는 영역(ROI)도 함께 저장해 원본 좌표로 되돌린다.

## 2. 올바르게 만들어졌는지 검증

| 검증 | 결과 |
|---|---|
| 실제 모델(20장): `cam`을 덧붙인 모델의 logits − 원본 logits | 최대 차이 **0.0** (한 비트도 안 바뀜) |
| 항등식 `mean(CAM) = (logit1−logit0) − (b1−b0)` 최대 오차 | **4.3e-06** |
| 출력 형상 | `[1,1,7,7]` |
| 작은 합성 모델 테스트 5건(`test_cam.py`) | 로짓 불변·항등식·**신호를 심은 칸에서 CAM이 변함(방향·부호)**·가중치 배치(transB)·지원하지 않는 구조 거부 |
| C#: `model_cam.onnx` vs `model.onnx` | 같은 이미지에서 점수 동일, `cam` 있는 쪽만 7×7 히트맵(`OnnxCamOutputTests`) |
| 추론 비용 | 장당 추론 평균 8.4 → 8.6ms(+0.2ms), 합계 19.8 → 20.0ms, 메모리 증가 없음(`VisionQC.Bench`, 50장×20회) |

## 3. 위치 정확도 (MVTec AD metal_nut 정답 마스크 기준)

`eval_cam.py` — 진짜 불량 93장(bent 25·color 22·flip 23·scratch 23)에 대해, 양의 CAM(불량 쪽 증거)을 정답 마스크와 비교(224px 입력 공간).
시험셋 14장은 학습·에폭 선택·임계값 선택에 쓰지 않은 이미지다. (CAM 자체는 학습 대상이 아니므로 전체 93장도 참고값으로 보고한다.)

| 구분 | 건수 | 포인팅 적중률 | 우연 기준 | 마스크 안 질량 | 마스크 면적 | lift (평균 / 중앙) |
|---|---|---|---|---|---|---|
| 전체 | 93 | **97.8%** | 30.2% | 23.5% | 14.5% | 3.25 / 3.36 |
| 시험셋 | 14 | **100%** | 29.7% | 23.9% | 15.4% | 3.75 / 3.96 |
| bent | 25 | 100% | 10.0% | 9.0% | 2.0% | 4.57 / 4.52 |
| color | 22 | 95.5% | 10.3% | 9.3% | 2.4% | 4.33 / 4.26 |
| scratch | 23 | 95.7% | 23.2% | 15.3% | 5.9% | 2.76 / 2.26 |
| flip | 23 | 100% | **78.3%** | 61.1% | 48.2% | 1.27 / 1.27 |

지표 정의
- **포인팅 적중률**: CAM 최댓값 칸(7×7 중 하나)이 정답 마스크와 한 픽셀이라도 겹치는 비율. **우연 기준** = 마스크와 겹치는 칸의 비율(그 칸을 무작위로 골랐을 때의 적중 확률).
- **마스크 안 질량**: 양의 CAM 총합 중 마스크 안에 있는 몫. **lift** = (마스크 안 질량) ÷ (마스크 면적) — 1이면 위치 정보가 없다.

## 4. 읽는 법과 한계 (정직하게)

- **잘 되는 점**: 가장 뜨거운 칸이 불량 위치를 우연보다 훨씬 잘 가리킨다(작은 불량인 bent·color에서 100%·95.5%, 우연 10%). 작업자가 "어디를 다시 볼지" 안내하는 용도로는 쓸 만하다.
- **한계 1 — 해상도**: 칸 하나가 입력의 32px이라 윤곽이 아니라 얼룩이다. 작은 불량은 마스크 안 질량이 9% 수준(면적 2%의 약 4.5배)에 그친다 — 열의 대부분은 불량 밖에 있다.
- **한계 2 — flip은 정보가 없다**: "뒤집힌 너트"는 마스크가 이미지의 절반 가까이를 덮어(면적 48%) 우연 적중률이 78%다. 100%라는 숫자는 위치 능력을 보여 주지 않는다(lift 1.27).
- **한계 3 — 표본**: 시험셋은 14장뿐이다. 한 카테고리(metal_nut)·한 촬영 조건의 결과이며 다른 제품에서는 다시 재야 한다.
- **한계 4 — 모델이 틀리면**: CAM은 "모델이 불량이라고 본 이유"이지 불량의 사실 위치가 아니다. 모델이 배경 특징(예: 조명 얼룩)에 반응해도 그곳이 뜨거워진다. 그래서 화면에는 "참고용"으로 표시하고 NG에만 겹친다.
- **박스·유형은 아직 없다**: 불량 위치를 박스로, 불량 유형을 라벨로 내려면 검출 모델이 필요하다(통계의 불량 유형 분포는 여전히 비어 있다). 검출 모델은 데이터셋 라이선스와 학습 프레임워크 라이선스(예: Ultralytics YOLO = AGPL-3.0)를 확인한 뒤 별도로 진행한다.

## 5. 재현

```bash
python training/add_cam_output.py --onnx training/out/model.onnx --out training/out/model_cam.onnx --data training/data
python training/eval_cam.py --model training/out/model_cam.onnx --data training/data \
       --src <압축 푼 MVTec 루트> --category metal_nut --split training/out/split.json
```
앱에서는 설정 탭의 모델을 `model_cam.onnx`로 지정하면 NG 결과에 히트맵이 겹쳐 보인다(검사·이력·재판정 화면, "불량 위치 히트맵" 체크로 끄기 가능). 화면: [08_불량위치히트맵.png](screenshots/08_불량위치히트맵.png)
